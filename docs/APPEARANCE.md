# 浅色与深色外观

主窗口侧栏底部新增「外观 / 浅色 / 深色」切换，位于打开悬浮窗按钮上方。窄屏导航布局保留外观区域。默认浅色，不跟随系统自动切换；主窗口的五个页面、加载/空/离线状态及浮窗使用同一套语义颜色。浮窗不再固定为深色。

浅色沿用白色/暖灰、橙色操作和黄色额度区域；深色以暖深灰为底，保留相同布局与状态语义。公共 CSS tokens 在 `src/ui/styles.css`，浮窗样式全部引用这些 tokens，避免维护第二套独立配色。

| 色彩用途 | 浅色 | 深色 |
|---|---|---|
| 背景 | `#ffffff` | `#1c1917` |
| 次级背景 | `#fafaf9` | `#211e1b` |
| 主文字 | `#0c0a09` | `#fafaf9` |
| 次级文字 | `#44403c` | `#d6d3d1` |
| 辅助文字 | `#78716c` | `#a8a29e` |
| 强调色 | `#ea580c` | `#fb923c` |
| 额度背景 | `#fef3c7` | `#352b12` |
| 边框 | `#e7e5e4` | `#44403c` |

## 行为与安全边界

- 外观切换不调用任何业务 Host 命令，不刷新 Provider，不修改账户、快照或 Keychain。
- 外观偏好仅保存固定键 `agent-quota.appearance.v1`，允许值仅为 `light` 或 `dark`。非法值/读取失败回退浅色。写入失败仍切换当前窗口，并明确提示未保存；不把未保存偏好广播给其他窗口。未保存的当前窗口选择不会被延迟完成的监听注册或旧同步事件覆盖，直到用户再次成功保存选择。
- `appearancePreference.ts` 是唯一写入入口；同步外部脚本 `public/appearance-bootstrap.js` 在 React bundle 执行前读取相同固定键并设置根节点主题，避免页面重载先显示浅色内容。同步脚本和关键背景 CSS 由本地资源提供，不新增外部资源或 CSP 放宽。
- Renderer 存储门禁仅对上述两个审阅过的适配器开放 SHA-256 精确文件例外。改变键、允许值或适配器内容必须重新审阅并更新 pin；其他 Renderer 文件的任意存储/网络访问仍被拦截，`public/*.js` 也纳入扫描。业务 DTO 和固定的 10 个业务命令保持不变。
- 同源 `storage` 事件与 Tauri `quota-appearance-changed` 事件同步偏好。事件内容仅允许 `light`/`dark`，收到后重读当前已提交偏好，防止旧事件覆盖较新的选择；接收方不重新写入或广播。异步监听注册完成后的卸载及重订阅均释放监听器。
- 原生窗口沿用 Tauri `window.setTheme`，仅追加 `core:window:allow-set-theme` 权限。当前依赖 API 注明 macOS 上该设置作用于整个应用；两个窗口目标主题一致。原生调用失败不阻断 Renderer 外观切换，不扩大文件或凭据权限。

## 验证与限制

新增单元测试覆盖默认值、重启后的偏好恢复、两窗口同步、非法载荷、延迟事件、订阅清理、存储失败和固定键限制。主窗口组件验证切换前后 Host 调用数保持不变。Renderer 门禁测试主动修改允许文件的存储键，并尝试其他模块的存储和网络调用，均应拒绝。

浏览器 E2E 覆盖主窗口五页面与浮窗同时切换、重载保持、390px 窄屏、空账户与离线两种外观；另将 React bundle 暂停加载，确认主窗深色根背景已先就绪、浅深浮窗的 HTML/Body 根背景始终透明。这证明网页内容初始化顺序，不证明 macOS 原生窗口创建阶段或标题栏的视觉表现。实际安装包的标题栏、跨 WKWebView 同步和退出重启由随包桌面验收记录另行确认，不以浏览器测试代替。

本轮没有改动 Provider 查询、额度计算、业务命令或凭据流程；未调用真实 Provider 接口。本说明不把源码与浏览器测试当作原生安装证据。
